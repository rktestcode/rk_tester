# RK3576 Unified Hardware Test Platform (rk_tester)

专为 Rockchip RK3576 4路千兆网卡开发板打造的**一站式全功能终端测试工具**（全 ASCII/英文界面，彻底杜绝任何终端乱码与方块字问题）。集成四路网卡静态 IP 自动配置与链路监控、四路网口高频两两互 Ping 丢包监测（EMC/ESD/EFT抗扰度测试）、RS232/RS485 两两对接持续单向数据传输测试、双路 CAN 总线测试、4路 USB 存储设备并发读写校验压测，以及 CPU/GPU/NPU/RGA/RKMPP 全负荷硬件烤机于一体。

---

## 一、4 路独立网口两两互 Ping 丢包监测（EMC/物理链路测试）

### 1. 什么是 4-LAN Dual-Pair Mutual Ping？
在工业控制与 EMC 实验室环境（静电放电 ESD、电快速瞬变脉冲群 EFT、浪涌测试）中，需要检验设备在受到强电磁干扰时，4 个千兆网口是否会出现瞬时丢包（Glitch）或网卡物理链路断开掉线（Link Flap）。
无需在外部连接 PC 电脑充当 Ping 目标，`rk_tester` 支持**两两网口通过网线物理直连互 Ping**：
- **第一组（Pair 1）**：`lan0` (`192.168.10.1/24`) <== 物理直连网线 ==> `lan1` (`192.168.11.1/24`)
- **第二组（Pair 2）**：`lan2` (`192.168.20.1/24`) <== 物理直连网线 ==> `lan3` (`192.168.21.1/24`)
- **独立子网防路由冲突**：4 个网口分别位于 4 个独立 `/24` 子网，既不影响 L2 `AF_PACKET` 两两互 Ping，也能确保任意单个网口直连外部 Windows/Linux 电脑时路由清晰、无 `rp_filter` 丢包与回包走错口问题。

### 2. 底层实现与物理链路穿透（独立 `poll()` 线程 + `AF_PACKET` 单播原始帧）
- **物理线缆穿透**：常规 Linux IP 栈在同主机不同网口间通信时会被内核回环（Loopback）自动拦截，无法检验外部物理线缆与 PHY/EMC 性能。`rk_tester` 底层采用 **Layer-2 `AF_PACKET` (`SOCK_RAW`) 原始数据包引擎**，以对端真实单播 MAC 构造标准以太网帧 + IP + ICMP 报文直接推送至物理网卡队列，报文必须穿过板载 PHY 芯片与外部实体网线到达对端网口，对端网口接收后再通过物理线缆反射 Echo Reply。
- **独立事件驱动线程**：EMC 发包/收包运行于独立的 `poll()` 事件驱动后台线程，与 TUI 渲染完全解耦，彻底消除轮询抖动，精准测量真实微秒级 RTT 延迟与 100ms 周期瞬态丢包。
- **抗电磁干扰评级**：实时统计丢包率与链路 Flap 次数，自动评级 `CLASS A`（0 丢包 PASS）、`CLASS B`（<1% 自恢复）、`CLASS C`（存在掉线或丢包 FAIL），并同步记录详细事件流水至 `/tmp/emc_test_*.log`。

### 3. 网线热插拔自动恢复与丢包精准记录（Hotplug Auto-Recovery & Loss Logging）
- **测试过程中拔下网线**：系统感知链路断开（`carrier` 掉线），准确记录物理掉线事件（`Link Flaps++`）。在断线期间，发包调度器如实计入已发送（Sent）与丢失（Lost），丢包率真实攀升至 100%，评级即时判定为 `CLASS C`。
- **重新插上网线**：底层驱动与 PHY 完成速率自协商后，软件自动检测链路复苏（Link Up）并读取真实协商速率，**零人工干预自动恢复互 Ping 发包与往返延时接收**，断线期间记录的丢包数据与 Flap 掉线计数完好保留。

## 二、4 路 USB 存储设备并发读写校验压测

针对开发板上的 4 个 USB 端口（默认对应 `sda`, `sdb`, `sdc`, `sdd` 存储介质），软件提供全自动的并发读写稳定性测试：

1. **后台自动挂载与自适应文件系统**：
   - 软件由独立后台线程检测并挂载至 `/mnt/rk_usb_test/{sda,sdb,sdc,sdd}`，绝不阻塞主监控界面与网络测试。
   - 自动筛选容量最大的数据分区（避开 EFI/MSR 保留分区），通过 `blkid` 动态识别文件系统类型，自适应 NTFS（`ntfs-3g`/`ntfs3`）、exFAT（`exfat`/`exfat-fuse`）、FAT32、ext4 等常见介质，并自动避开系统根分区。

2. **安全非破坏性测试（Non-destructive）**：
   - **绝对不破坏分区表，不影响原有用户数据**。
   - 测试通过在挂载目录下生成隐藏临时测试块（`/.rk_test_io_slot<N>.dat`）进行循环读写验证。

3. **并发高强度读写与真实硬件介质校验**：
   - 4 颗独立线程同时对 4 路 USB 设备以 1MB 数据块循环执行：写入 -> `fdatasync` 强制落盘 -> `posix_fadvise(POSIX_FADV_DONTNEED)` 驱逐内核页缓存 -> 从硬件重新读取 -> 内存逐字节校验（`memcmp`） -> 删除临时文件，杜绝页缓存假阳性。
   - 界面实时显示总写入/读取量（MB）、总写速与读速（MB/s）、错误次数与各盘详情；退出时打印含设备型号、容量、挂载点与校验结果的完整报告。

4. **U 盘/移动硬盘热插拔自动恢复与盘符漂移自愈**：
   - **测试过程中拔下设备**：工作线程立即捕获 I/O 中断，精准递增错误计数（`errors++`）与掉线计数（`disconnects++`），后台执行 `umount -l` 清理失效挂载点，界面即时红色报警 `[DISCONNECTED (xE)]`。
   - **重新插上设备**：通过 sysfs USB 物理拓扑路径自动识别并恢复（即使内核因 FUSE 占用将原 `sda` 重分配为 `sde` 也能自动重新绑定），自动挂载并无缝恢复读写校验（`recovers++`）。

5. **快捷键控制**：按 **`8`**（或 `U`）随时开启 / 暂停 4 路 USB 读写压测。

## 三、RS232 与 RS485 传输测试（支持正向 / 反向 / 交替应答）

开发板板载多组 UART，硬件两两对接，软件提供高可靠性数据流测试，均支持 **正向单向、反向单向、半双工 Ping-Pong 交替应答** 三种模式：
1. **RS232 对接通道（`/dev/ttyS0` <-> `/dev/ttyS1`）**：
   - 按 **`6`** 开启 / 暂停，按 **`Z`** 随时切换方向：`S0 -> S1 (Uni)` ➔ `S1 -> S0 (Uni)` ➔ `S0 <-> S1 (Ping-Pong)`。
   - 启动参数：`--rs232-0to1` / `--rs232-1to0` / `--rs232-pingpong`。
2. **RS485 对接通道（`/dev/ttyS2` <-> `/dev/ttyS3`）**：
   - 按 **`7`** 开启 / 暂停，按 **`X`** 随时切换方向：`S2 -> S3 (Uni)` ➔ `S3 -> S2 (Uni)` ➔ `S2 <-> S3 (Ping-Pong)`（Ping-Pong 模式采用 30ms 轮询应答，适配半双工 RS485 无总线碰撞）。
   - 启动参数：`--rs485-2to3` / `--rs485-3to2` / `--rs485-pingpong`。
3. **全载荷逐字节校验、平滑切向防误报与实时通信状态**：
   - 波特率 `115200 8N1`，发送 64 字节结构化数据帧（同步头 `0xAA55` / `0x55AA` + 递增序列号 + 58 字节动态载荷 + 16 位校验和）。
   - 接收端同时验证校验和并对**全部 58 字节载荷进行逐字节比对（`memcmp`）**（Ping-Pong 模式下对端先全载荷校验 Ping 后取反回发 Pong，源端再次全载荷比对），500ms 未收到匹配帧记入超时丢帧；切换方向时自动插入 60ms 静默排空窗口，彻底消除频繁切向误报。
   - **状态与错误解耦**：累计错误次数在 `E:` / `CRC:` 持续统计并标红；右侧实时状态仅反映当前链路状态（`[COMM]` 正常通信、`[WAIT]` 等待建链、`[NORX]` 当前断收、`[IDLE]` 待机），发生瞬时错误恢复后自动回归 `[COMM]`。

## 四、CAN0 与 CAN1 传输测试（支持单向与交替应答）

开发板板载两路 CAN 总线控制器（`can0` 与 `can1`，硬件两两直连对接），基于 SocketCAN 提供高可靠性压测：

### 1. 支持的三种测试模式（随时按 `D` 切换）
1. **模式一：`CAN0 -> CAN1 (Uni)`（默认推荐）**：CAN0 每 20ms（50 fps）发送 8 字节标准帧（ID `0x121`，同步字 `0xC0`），CAN1 负责接收并校验，零总线仲裁冲突、故障定位精准。
2. **模式二：`CAN1 -> CAN0 (Uni)`（反向单向）**：CAN1 每 20ms 发送 8 字节标准帧（ID `0x221`，同步字 `0xC1`），CAN0 接收校验。
3. **模式三：`CAN0 <-> CAN1 (Ping-Pong)`（半双工交替应答）**：CAN0 发送 Ping -> CAN1 校验后回复 Pong -> CAN0 匹配在途帧序号完成闭环验证。

### 2. 自动链路拉起、硬件总线错误监控与丰富展示
- 自动检测 `IFF_UP` 状态，优先按 CAN-FD（500k / 2M）拉起，不支持时自动回退标准 500kbps CAN 2.0。
- 开启 `CAN_RAW_ERR_FILTER` 硬件错误帧监控，实时捕捉 Bus-Off、ACK 缺失、位错误并统计 `Bus` 总线错误计数。
- 接收端对**全部 8 字节数据帧进行校验和 + 逐字节一致性比对**（Ping-Pong 模式下回发异或变换载荷并在源端逐字节校验），状态栏同样以 `[COMM]`/`[WAIT]`/`[NORX]`/`[IDLE]` 反映实时通信状态，历史错误在 `E:`/`CRC:`/`Bus:` 持续累计；切换方向自动插入 30ms 静默排空窗口。

### 3. 启动参数与切换方式
- **运行中切换**：主界面或菜单内按 **`D`** 循环切换 CAN 方向（在菜单中光标停在 RS232/RS485 时按 `D` 也可切换对应串口方向）。
- **启动参数**：`sudo rk_tester --can-0to1` / `--can-1to0` / `--can-pingpong`。

## 五、四大独立硬件功能板块与高对比度仪表盘布局

仪表盘按硬件功能域划分为 **4 个独立板块**，配高对比度彩色实体徽标栏与动态自适应布局：
1. **【板块 1：计算加速与 SoC 监控】`[1-4,0,V] COMPUTE & SOC ACCELERATORS`（青底黑字）**：CPU 8 核（4×A53 + 4×A72）负载与主频、Mali-G52 GPU（Panfrost EGL/GLES）压测、RK-NPU 双核 6 TOPS 矩阵压测、RGA2 双核 4K 2D CSC/旋转压测、RKMPP 双通道 4K H.265 VENC+VDEC 编解码并发压测、内存占用与 SoC/Big/GPU/NPU 温度。
2. **【板块 2：四路千兆以太网与 EMC 监测】`[5] 4-PORT GIGABIT ETHERNET`（绿底黑字）**：4 路网口物理链路状态、速率、发包/收包/丢包率、微秒级 RTT、EMC 综合评级与事件流水。
3. **【板块 3：工业现场总线测试】`[6,7,9] INDUSTRIAL FIELDBUS`（黄底黑字）**：RS232、RS485 与 CAN 总线实时速率、帧率、错误计数与状态标签。
4. **【板块 4：高速 USB 存储读写压测】`[8] 4-PORT USB STORAGE`（蓝底白字）**：总读写量与速率汇总 + 4 路独立盘体实时状态。
5. **动态终端自适应**：自动适配紧凑模式（最小 `76x23`，标准 `80x24`）与宽屏模式（高度 `>= 30` 行展开 8 核图形条与以太网事件流水）。

## 六、测试项勾选配置菜单（交互式 Checklist 菜单）

随时按 **`M`** 或使用 `sudo rk_tester -m` 启动即可呼出交互式勾选菜单：
- **`↑` / `↓` / `←` / `→`**：移动光标选择测试项、网口过滤项或操作按钮。
- **`Space` / `Enter`**：切换勾选状态 `[X]` / `[ ]`。
- **`0..9` / `V`**：快速切换对应测试项（`0`=RGA，`V`=RKMPP，`4` 快速切换 CPU+GPU+NPU+RGA+RKMPP 五引擎全烤机）。
- **`Z` / `X` / `D`**：分别切换 RS232 / RS485 / CAN 传输方向（光标停在 RS232 或 RS485 上时按 `D` 也可直接切换该项方向）。
- **`A` / `N`**：一键全选 / 全清。
- **`S`** 或选中 `[ Apply & Run ]` 回车：应用勾选配置并自动保存至 `/etc/rk_tester.conf`（下次启动自动记住上次选择）。
- **`ESC` / `M`**：取消并返回仪表盘。
- **配置记忆机制**：无论通过菜单应用还是主界面快捷键切换（测试开关、网口过滤、串口/CAN 方向、调频策略），都会自动持久化到 `/etc/rk_tester.conf`；下次直接运行 `sudo rk_tester` 自动恢复并启动上次选中项，运行 `sudo rk_tester -m` 自动回填上次勾选状态，加上 `--no-restore` 可跳过恢复。

## 七、网线接线说明（两两互联测试）

**无需外部测试电脑与交换机，两根标准网线即可测试 4 个千兆网口：**
- **第一组**：一根网线直连开发板 **`Port 1 (lan0: 192.168.10.1/24)`** 与 **`Port 2 (lan1: 192.168.11.1/24)`**。
- **第二组**：另一根网线直连开发板 **`Port 3 (lan2: 192.168.20.1/24)`** 与 **`Port 4 (lan3: 192.168.21.1/24)`**。
- **单口直连 PC 调试**：将 PC 网卡设为对应网段 IP（如接 `lan1` 时将 PC 设为 `192.168.11.100/24`）即可直接 ping 通 `192.168.11.1`，亦可在 Windows 网卡高级 TCP/IP 设置中一次性绑定 `.10.100` / `.11.100` / `.20.100` / `.21.100` 四个地址实现免改 IP 随插即通。
- **原有 SSH 连接保护**：测试 IP 以附加 IP 方式配置，原有管理 IP 与 SSH 会话不受影响；若仅接入第一组网线，可在菜单（按 `M`）中取消勾选 `lan2`/`lan3` 避免未接网口计入丢包。

## 九、编译与运行

### 1. 源码模块结构
```text
src/
├── common.{hpp,cpp}        # 公共常量、信号退出标志、校验和与工具函数
├── accel_burn.{hpp,cpp}    # 内置 GPU (Panfrost EGL/GLES) / NPU (RKNN) / RGA (IM2D) / RKMPP (H.265 编解码) 原生压测工作进程
├── serial_tester.{hpp,cpp} # RS232 / RS485 收发校验引擎
├── can_tester.{hpp,cpp}    # SocketCAN 收发校验与总线错误监控引擎
├── usb_tester.{hpp,cpp}    # 4 路 USB 存储自动挂载、漂移恢复与读写校验引擎
├── net_emc.{hpp,cpp}       # 4 路千兆网卡 AF_PACKET 互 Ping 与 EMC 监测引擎
├── soc_engine.{hpp,cpp}    # SoC 监控与 CPU/GPU/NPU/RGA/RKMPP 压测调度总控
├── config_store.{hpp,cpp}  # 测试配置持久化 (/etc/rk_tester.conf)
├── tui.{hpp,cpp}           # ncurses 仪表盘、勾选菜单与退出汇总报告
└── main.cpp                # CLI 参数解析与程序主入口
```

### 2. 编译安装
```bash
make -j$(nproc)
sudo make install
```

### 3. 启动测试
```bash
# 查看命令行帮助（无需 sudo，零副作用）
rk_tester --help

# 默认启动（直接进入主监控仪表盘，按 M 可随时呼出勾选菜单）
sudo rk_tester

# 开机直接进入测试项勾选菜单模式
sudo rk_tester -m

# 指定 CAN 初始测试方向启动
sudo rk_tester --can-pingpong
```
